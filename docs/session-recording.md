# 联调会话录制与回放

在主窗口选择「联调录制」。TestTool 监听一个地址，把收到的字节原样转发给指定上游，同时记录两个方向的报文。代理不修改 HTTP Host、路径或任何业务字段。

## 接入真实联调

本公司访问对方：将本公司业务系统的目标改为 TestTool 的监听地址，上游填写对方真实地址。

```text
本公司业务系统 → TestTool:9000 → 对方服务:8000
```

对方访问本机：把本机业务服务改到 8001，由 TestTool 监听原来的 8000；也可以让对方改为访问新的代理端口。

```text
对方系统 → TestTool:8000 → 本机业务服务:8001
```

监听和业务服务不能占用同一地址、同一端口。默认监听 `127.0.0.1`；需要其他机器访问时，填写可访问的本机地址或 `0.0.0.0`，并按实际网络环境放通该端口。代理建立新的上游连接，上游看到的网络来源为 TestTool 所在机器，无法保留原客户端的源 IP。

## 录制配置

1. 填写会话名称、协议、监听和上游地址。
2. TCP 选择 ASCII 十进制长度头（长度表示正文的字节数）、十六进制分隔符，或连接关闭分帧。编码只用于查看文本和解析 JSON，不影响原始转发。
3. 明确关联方式。关联字段留空代表严格一问一答、按当前连接内的顺序关联；对长连接并发、乱序、主动推送，应填写双方报文共有的 JSON 流水号路径，例如 `$.requestId`。支持点路径及数组数字索引，不支持完整 JSONPath 表达式。
4. 点击「开始代理录制」，再发起业务联调。录制完成后点击「停止并保存」。

HTTP/1.1 支持 Content-Length、chunked、连接关闭响应体、HEAD 和临时响应；WebSocket 支持握手、文本/二进制消息、分片和控制帧。当前不解析 HTTP/2、CONNECT 隧道、TLS 明文或 WebSocket 压缩扩展。HTTPS/WSS 加密流量可经过 TCP 字节转发，但无法直接生成业务级回放规则；需要在可获取明文的位置接入代理。

连接关闭分帧需要发送方真正关闭发送方向。若双方都等待对方先关闭，则应配置业务协议的长度头或分隔符；代理不会把一次 `recv()` 或空闲间隔当成一条业务报文。

## 查看与修正关联

- 「请求 / 响应」展示来源、真实上游、交互状态、关联方式和响应耗时。
- 「全部消息」包含未关联响应、WebSocket 握手、控制事件及不完整字节。选择消息可查看文本、业务正文 Hex 和原始线路字节。
- 「连接」展示连接失败、空闲超时、取消及其他错误。没有响应时保留请求与错误状态，不把错误提示存为对方的报文。
- JSON 字段缺失、同一连接多个未完成请求使用同一流水号时，不自动猜测配对。停止录制后使用「人工配对请求与响应」修正；可在同一会话内跨连接配对。一个响应只能属于一条交互。

列表展示最近 500 条交互/消息；详情预览前 64 KB。数据库保存完整原始数据，JSON 导出包含全部记录。会话时间列使用 UTC，消息时间按本机时间显示。

## 离线 Mock

1. 选择有完整响应的交互，点击「生成回放规则」。
2. 精确匹配比较请求正文原始字节。HTTP 同时比较方法与路径（包含查询串），不比较请求头；WebSocket 同时比较文本/二进制类型。
3. JSON 字段匹配填写逗号分隔的稳定字段，如 `$.tradeCode,$.orderId`。
4. 可填写「回填字段」，例如 `$.requestId`：把当前请求中该字段复制到响应相同路径。请求和响应都必须包含该字段；修改内容后自动重算 TCP 长度头或 HTTP Content-Length。压缩 HTTP 响应不能直接回填 JSON。
5. 选择延迟；默认采用录制响应耗时，上限 60 秒。
6. 停止代理后，在「录制 Mock 规则」启动 Mock。其监听地址取顶部当前值，协议、编码和分帧配置取所选会话保存的配置。业务系统改为访问该监听地址即可离线联调。

无规则命中时 HTTP 返回 404，其余协议关闭连接并显示原因；多规则命中默认报错。选择顺序回放后，同一组命中规则按规则创建顺序返回，每个连接有独立位置，全部用完后报错，不自动循环。规则变化在重启 Mock 后生效。

当前回放面向收到请求后返回响应；不自动重现主动推送、跨连接业务状态或网络故障。回填字段也不会自动重签签名/MAC，需按业务协议处理后使用。

## 保存到原有协议测试

- 「生成客户端用例」新建协议测试集合与目标，将请求保存为可编辑预设，将请求响应原始字节和预期响应保存为历史记录。
- 「保存为固定 Mock」同时生成关联目标与固定返回的服务端配置。需要根据请求匹配不同返回时，使用本页的录制 Mock。
- 原有客户端/固定 Mock 不支持分隔符 TCP 或二进制 WebSocket，用本页录制 Mock 回放。不能无损转换为选定编码的二进制报文也不导出为文本固定响应；原有 HTTP 文本用例和固定响应使用 UTF-8。客户端用例的二进制预期响应仍在历史中保留原始字节。
- 「导出 JSON」在后台导出会话、连接、事件、关联和回放规则；字节字段使用 Base64。该文件用于归档，目前不提供 JSON 会话导入。

录制与规则都保存在当前 SQLite 数据库中；重启后选择历史会话即可回放。「加载配置」可恢复原录制参数。导出客户端用例、历史和固定 Mock 使用同一数据库事务，失败时整体回滚。

## 资源与停止

最多 200 个同时连接。网络使用双向缓冲背压，支持 TCP 半关闭；停止时关闭活动连接并等待线程结束。单条业务报文上限 10 MB，单连接未响应请求上限 1000；持久化队列最多 512 个事件及 32 MB 待写字节。解析、写库失败或队列溢出时明确提示会话不完整，网络转发继续进行。不完整消息保留原始字节，不能生成正常响应规则。
